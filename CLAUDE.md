# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

İhbarBot semi-automates filing a Turkish traffic-violation report (112 trafik ihbarı) from dash-cam footage on [ihbar.ng112.gov.tr](https://ihbar.ng112.gov.tr). It OCRs the GPS overlay and timestamp burned into a dash-cam video, reverse-geocodes the coordinates to an address, and drives Chrome via Selenium to fill out the official report form. The bot **only fills the form** — hCaptcha and SMS confirmation are always done by hand, and submission is always under the user's control.

**The site was rebuilt in August 2026 (v1.1.38) and the form is now a three-page wizard.** The evidence upload no longer accepts video at all — only jpg/jpeg/png up to 5 MB — so the pipeline extracts a still frame from the dash-cam video and uploads that instead. See "Site-specific quirks" below.

This is a personal-use tool, not a library or service. There is no test suite, linter, or build step.

## Requirements & running it

- macOS only — OCR shells out to the `swift` CLI (Xcode Command Line Tools) to run `ocr_helper.swift`, which uses the native Vision framework.
- `ffmpeg` must be installed (`brew install ffmpeg`) — used to extract still frames from video.
- Chrome + Selenium (ChromeDriver is auto-managed by Selenium 4.46+).
- Personal info lives in `config.json` (gitignored), copied from `config.example.json` — `form_filler.py` reads it at import time and calls `sys.exit(1)` if it's missing.

Run:
```bash
source venv/bin/activate
python3 app.py      # Tkinter GUI (primary entry point) — or double-click İhbarBot.command
python3 main.py     # CLI/terminal version, same pipeline, blocking input() prompts
```

There are no automated tests. To verify a change, actually run `app.py` or `main.py` against a video in `videolar/` and watch it drive the real site (or check module behavior in a `python3 -c` snippet for pure logic like `ocr_helper.parse_coordinates`/`parse_datetime`).

## Architecture

Both entry points (`app.py` GUI, `main.py` CLI) wire together the same three pipeline modules in the same order:

1. **`ocr_helper.py`** — `analyze_video_metadata(video_path)`: extracts frames via `ffmpeg` at increasing timestamps (1s, 3s, 5s, 10s, 20s, 40s), runs each through `ocr_helper.swift` (macOS Vision OCR, invoked as a subprocess), and parses GPS coordinates + datetime out of the recognized text lines. It keeps sampling later frames until both fields are found, because the GPS overlay is often blank on the very first frame (no fix yet). Coordinate/datetime parsing (`parse_coordinates`, `parse_datetime`) has to work around OCR artifacts: spaces injected inside decimals, values split across two lines, and stray spaces around `/`/`.`/`:` separators.

   Each frame is read more than once. The GPS overlay is small relative to a 2560×1440 frame, and on the full frame Vision routinely drops part of it — a VIOFO A119 Mini 2 clip reads as `N40.900480` + a bare `367887`, with the `E29.` gone, which leaves longitude unresolvable. `ocr_frame_variants()` therefore retries the same frame through the `OCR_VARIANT_FILTERS` list (`apply_video_filter()` → ffmpeg crop + lanczos upscale + contrast): raw frame first, then the bottom-left corner at 3×, the full bottom strip at 2×, then the top-left corner for cameras that stamp their overlay at the top. It stops at the first variant that completes the picture, so clips that already worked on the raw frame cost nothing extra. `parse_coordinates` also tolerates OCR junk around the hemisphere letter (`_E29`, `E29™`, `E29` on its own line) and discards values outside ±90 / ±180.

2. **`geocoder.py`** — `reverse_geocode(lat, lon)`: wraps `geopy`'s Nominatim reverse geocoder, returning a dict with keys `il`/`ilçe`/`mahalle`/`sokak` (province/district/neighborhood/street), each defaulting to `'Bilinmiyor'` if unresolved. Nominatim returns no `road` at all when the coordinate lands on a road segment that has no `name` in OSM (common on Turkish trunk roads and slip lanes — e.g. `40.900480,29.367887` falls on way/187213433, tagged only `highway=trunk`), which used to leave the street empty even though the road plainly has a name. `nearest_named_road()` covers that case: an Overpass query for named `highway` ways within 250 m, scored by true distance to each way's geometry, with motorway/link types deprioritized because those names never appear in the report form's street dropdown. It uses `urllib` (no new dependency) and degrades to `'Bilinmiyor'` on any network failure. `official_mahalle()` covers a second Nominatim weakness: its `suburb`/`quarter` keys return the *semt* (informal locality), which is not always the official mahalle — at `40.964543,29.103548` Nominatim says Kozyatağı Mahallesi while the point is inside Bostancı Mahallesi, and the report form's street list is filtered by mahalle, so the street simply never appears. A second Nominatim reverse call at `zoom=13` returns the administrative boundary relation that *contains* the point (point-in-polygon, not nearest feature) and wins over those keys; the result must be the boundary itself (`category=boundary`, name ending in `Mahallesi`), because zoom 14 and above answer with the semt node again. Until 14.09.2026 this was an Overpass `is_in` query, and on that day all three Overpass mirrors were returning 504s and timeouts: every address lookup stalled for about a minute and then silently fell back to the error-prone Nominatim keys. Overpass is now only the fallback, with a shorter per-mirror HTTP timeout (`OVERPASS_HTTP_TIMEOUT_SEC`), and once every mirror has failed `_overpass()` is skipped for `OVERPASS_ARA_SN` (5 minutes) so a single outage does not cost the same wait on every lookup — this also covers `nearest_named_road()`. The two Nominatim calls are spaced by `NOMINATIM_ARA_SN` to stay within Nominatim's one-request-per-second policy. Because a street running along a mahalle border legitimately belongs to both, `reverse_geocode()` also returns `mahalle_adaylari` — an ordered candidate list that `form_filler` walks through until the street is actually found in the site's list.

3. **`drive_uploader.py`** — the site drops videos silently (see "Site-specific quirks"), so the clip itself can only reach the police as a link. `upload_and_get_link(video_path)` shells out to `rclone` to copy the video into a fixed Drive folder and then `rclone link` it, which is what flips that one file to "anyone with the link". `append_link_to_description()` glues the resulting URL onto the report text — the site's description whitelist already allows `: / . - _ ? = & %`, so Drive URLs survive `sanitize_for_site()` unchanged. The URL is not written verbatim: `armor_link_for_site()` percent-encodes the uppercase letters of the file id so it survives the description field's case transforms (see "Site-specific quirks"). Only the uploaded file is shared; the folder stays private, so one report's link does not expose the rest of the archive. `rclone` is used rather than `google-api-python-client` because it ships its own verified OAuth client — no Google Cloud project, and no 7-day refresh-token expiry from an unverified test app. Setup is one-time (`rclone config create gdrive drive`); `is_configured()`/`setup_hint()` let the GUI and CLI warn up front instead of failing mid-automation. Remote name and folder id live in `config.json` (`drive_remote`, `drive_klasor_id`).

4. **`form_filler.py`** — `IhbarFormFiller.fill_form(address_info, image_path, description_text, wait_callback=None, guvenlik_birimi="Emniyet", gorsel_yukle=True)`: drives the actual Selenium automation against the live site. The second argument is now an **image** path (jpg/jpeg/png), not a video. `_fill_steps()` walks the three wizard pages and returns a bool; `fill_form()` calls it a second time with no image if the first (image-carrying) attempt gets stuck, because the site's file scan can lock the form irrecoverably. **`fill_form()` returns whether the report was actually submitted** — i.e. whether the final `Devam Et` click landed and the SMS stage was reached — and callers must write to `ihbar_gecmisi.json` only on `True`. Until 10.09.2026 the final click's failure was swallowed by `_click_element()`, so a run where the user had closed the browser still walked on to the SMS prompt and recorded a report that was never filed; a false history row is worse than no row, because it makes the same vehicle look already-reported. `_click_element()` now returns a bool, and `tarayici_kapandi_mi()` recognises a vanished browser in both of its shapes — `invalid session id` (window closed, chromedriver alive) and urllib3's `connection refused` (chromedriver gone) — so the log gets one sentence instead of a 20-line chromedriver stack (`kisa_hata()` trims the rest). This is the most fragile and most-tuned part of the codebase — see "Site-specific quirks" below. `wait_callback(step, prompt_text)` is how the GUI and CLI differ: the GUI passes a callback that blocks a background thread on a `threading.Event` until the user clicks "Devam Et" in the UI (see `app.py`'s `wait_callback`/`trigger_resume`); the CLI passes `None` and falls back to blocking `input()`.

5. **`ihlal_katalogu.py`** — maps the free-text incident description to its counterpart in 2918 sayılı Karayolları Trafik Kanunu, so the report carries the article the police would cite (which is also what makes the report usable as a fahri trafik müfettişi record). `eslestir(metin)` normalizes both sides through `normalize()` — Turkish letters folded to ASCII, punctuation collapsed — so `kırmızı ışık ihlali` and `kirmizi isikta gecti` reach the same entry, and **the longest matching keyword wins**: `park` (4 chars) must not beat `kaldirimda park` (15), or a sidewalk parking report would be filed under the wrong bent. `dayanak_ekle(aciklama, ihlal=None)` appends one `Kanuni dayanak: …` line and returns `(metin, ihlal)`; when nothing matches it returns the text untouched, because inventing an article for an official police report is worse than omitting one. Both entry points print a warning in that case.

   The 39 catalog entries — madde/bent, the guide's own wording of the violation, and the ceza puanı — were transcribed from EGM's official `2026 Yılı Trafik İdari Para Ceza Rehberi` PDF (`KAYNAK_URL`), not from memory or from the law-firm blogs that dominate search results; those still quote pre-7574 amounts (they say kırmızı ışık is 2.719 TL when the guide says 5.000 TL). **`tutar` is deliberately never written into the report** and only shown on screen: 7574 sayılı Kanun (27.02.2026) tied many items to fixed amounts that then *escalate with the offender's repeat count within one year* (kırmızı ışık runs 5.000 → 80.000 TL over six offences), and we cannot know which offence this is. `ceza_puani` is `None` for the few 46/2 bents whose point column the guide leaves empty; `dayanak_metni()` omits the parenthetical in that case.

   Every string in the catalog must stay spelled with real Turkish letters and inside the description whitelist — the emitted line goes through `sanitize_for_site()` and the site's `toLocaleUpperCase("tr")` untouched only because `madde 47/1-b` uses just `/`, `-`, `.` and `()`. A side effect worth knowing: the dayanak line alone is ~100 characters, so reports that used to trip the 50-character minimum now clear it.

`main.py` also owns four small helpers reused by `app.py`: `find_video_in_folder()` (first video file found in `videolar/`), `parse_plates_from_filename()` (extracts one or more Turkish plates from the video filename via `PLATE_PATTERN`, e.g. `34ABC123 06XYZ789.mp4` or `74AAY507,34PH7806.mp4` → two plates; `plakalari_ayikla()` does the splitting and treats **any** non-alphanumeric run as a separator, because typing a space into a filename in Finder is awkward and commas get used instead), `find_image_in_folder()` (a ready-made jpg/png dropped into `videolar/` wins over frame extraction) and `prepare_image_from_video()` (ffmpeg still frame → `gorseller/<video>_<n>s.jpg`, the file actually uploaded).

The GUI's "Olay Detayı Açıklaması" field is an **editable** `ttk.Combobox` listing `ihlal_katalogu.etiketler()` — picking an entry is a shortcut, not a constraint, and a hand-typed description is still matched. `_update_dayanak()` runs on a `trace_add("write")` so the resolved article is visible before the run starts; `start_automation()` reuses the already-matched `self.eslesen_ihlal` instead of re-matching, and `add_history_entry()` stores its `madde` in `ihbar_gecmisi.json`. The CLI equivalent is `olay_detayi_sor()`, which prints the numbered catalog and accepts either a number or free text.

`app.py` is a Tkinter GUI wrapping the same pipeline in background threads, communicating back to the main thread via a `queue.Queue` polled with `root.after(100, ...)`. It also persists in-progress form state to `session.json` (gitignored) so a partially-filled report survives an app restart. `sys.stdout` is redirected to the on-screen console log widget (`StdoutRedirector`), so `print()` calls throughout the pipeline modules are the actual logging mechanism — there is no logging framework. "TÜMÜNÜ TEMİZLE" (`clear_fields`) does more than reset the visible fields: it also sets `wait_event`, which unblocks a background automation thread that's currently parked in `wait_callback` waiting on hCaptcha/SMS input — without this, clearing the form mid-automation would leave that thread hung forever.

## Site-specific quirks (ihbar.ng112.gov.tr, v1.1.38)

These are load-bearing workarounds baked into `form_filler.py`; don't "simplify" them away:

- **The form is three separate pages**, not one: `/ihbar-olustur/olay-vaka-konumu` → `/ihbar-olustur/olay-vaka-detayi` → `/ihbar-olustur/kisisel-bilgiler` (`STEP_URLS`). Each page has its own `Devam Et` (`button[type=submit]`), which stays `disabled` until that page's form validates. `_click_devam_et()` waits for the button to enable, clicks it, then waits for `EC.url_contains` of the next step. **Reloading any step page throws you back to step 1** — the wizard keeps its state in Redux with no persistence, so recovery means refilling from the start (that's exactly what the no-image retry does).
- **An intro modal ("HAYAT 112 Mobil Uygulaması") covers the form on load** and blocks real clicks; `_dismiss_promo_modal()` clicks its `type=button` "Devam Et" first.
- **Uploads are images only** — `accept="image/png,image/jpg,image/jpeg"`, `id="file"`, **5 MB cap** (`if (file.size > 5242880) throw FILE_SIZE_ERROR`, not 15 MB), and the type check reads the file's magic bytes (JPEG `FF D8 FF`, PNG `89 50 4E 47 …`), so a renamed file is rejected as `FILE_TYPE_MISMATCH`. Anything over 1 MB is re-compressed to JPEG client-side by Compressor.js (quality .6, max 4096×4096) before that check runs.
- **Handing the site a video looks like it works and silently drops it.** The uploader is an Ant `Dragger` with `beforeUpload: file => (validate(file), false)`. Returning `false` keeps the file in Ant's own `fileList`, so the preview card renders — but `validate()` is async: for anything over 1 MB it first runs Compressor.js, which throws on a video, so `props.onChange(file)` is never reached and the file never enters Redux or the `POST /api/scan-file` call. The `catch` then sets scan status to `CLEAN`, which **enables `Devam Et`**, and the error toast only fires for the component's own error class — a Compressor failure produces no message at all. Net effect: the card is visible, the wizard advances, and the report is filed with no evidence attached. This is why the pipeline always uploads an extracted still, never the video.
- **The file scan is currently broken server-side, and it locks the form.** On upload the page POSTs to `/api/scan-file` and polls `/api/analyse-scan-report`; while the status is `IDLE`/`SCANNING` the `Devam Et` button is disabled. As of 19.08.2026 that POST never returns (stays pending indefinitely, regardless of file size or type), and the upload card renders only a spinner — no remove icon — so the file cannot be taken back out of the form. There is no in-page recovery: `_wait_for_file_scan()` gives up after `SCAN_TIMEOUT_SEC` and `fill_form()` restarts the whole wizard without the image. The GUI's "Görseli yükle" checkbox skips the attempt entirely.
- **The description field force-uppercases everything you type, in Turkish locale.** Its handler is `onChange: e => setFieldValue("description", e.target.value.toLocaleUpperCase("tr"))`, so `i`→`İ` and `ı`→`I`. Two consequences: (a) any ASCII-ified Turkish you write comes back wrong (`kaydi` → `KAYDİ`), so text destined for this field must be spelled with real Turkish letters (`kaydı` → `KAYDI`); (b) it destroys anything case-sensitive, notably a Google Drive file id.
- **On blur the site rewrites links inside the description.** `onBlur` POSTs the whole text to `/api/detect-url`, gets back `detectedLinks: [{start, end, href}]`, and splices each `href` into the text via `setFieldValue(..., false)` — bypassing the uppercase transform. The server returns the href **lowercased with Turkish rules**, so every URL in the description goes through a full `upper → lower` round trip. An all-lowercase URL survives that round trip unchanged; a mixed-case one does not, and the original casing is unrecoverable (this is why hand-fixing `İ`→`I` cannot repair a broken Drive link). `drive_uploader.armor_link_for_site()` therefore percent-encodes the uppercase letters of the file id (`%4F` and `%4f` both decode to `O`), and `_verify_description_links()` reads the field back after the round trip and warns loudly if the id no longer matches — a broken link is otherwise completely silent. Google serves the percent-encoded form normally (verified 10.09.2026).
- **Links in the description are virus-scanned and block the step while scanning.** After `detect-url`, the page POSTs the URLs to `/api/malware-scanner` and polls `/api/get-analyse-report` every 10 s; while a link is unscanned the description carries a `SCANNIG_LINKS` field error and `Devam Et` stays disabled (`VIRUS_DETECTED_LINK_DESC` if `hasVirus > 5`). That is why the step-2 → step-3 `_click_devam_et()` uses a long `enable_timeout`.
- **The description field requires at least 50 characters** (`description.min(50)`); below that the step-2 button never enables. `app.py`/`main.py` both check this before starting.
- **Per-field character whitelists**, enforced by yup regexes and mirrored in `sanitize_for_site()`: description allows ``0-9 A-Z a-z (TR) space ! @ # $ % & ( ) _ + - = : " ' , . ? / …`` (so `* < > ^ | ; { } [ ] \` are stripped); the personal address field allows only letters/digits/space/`.`/`/`/`-` and must be 10–200 chars; phone must be 10–11 digits and must not start with `90`.
- **Never type character-by-character into form fields.** The site's React app has a token-check loop that per-character `send_keys` input events trigger, crashing the page with React error #185 ("Maximum update depth exceeded"). All fields are filled via `_js_fill()`, which uses the native `HTMLInputElement`/`HTMLTextAreaElement` value setter and dispatches a single `input`/`change` event. Per-char `send_keys` is only used as a last-resort fallback when JS-fill verification fails.
- **The location dropdowns are a customized Ant Select — the selected value is not where Ant puts it.** There is no `span.ant-select-selection-item`; the chosen option lives in `div.ant-select-content` (its `title` attribute and text, plus an `ant-select-content-has-value` class), while the `#cityDropdown`/`#streetDropdown` search input's own `value` is cleared after selection. `_dropdown_value()` reads that div, and it is the only reliable way to tell a real selection from a click that did nothing.
- **Closed dropdown popups stay in the DOM.** Ant only adds `.ant-select-dropdown-hidden`, so a document-wide search for `.ant-select-item-option` also matches the *previous* field's options; the matcher then "selects" an invisible option belonging to another select and the field silently stays empty. Option lookup must be scoped to `.ant-select-dropdown:not(.ant-select-dropdown-hidden)`.
- **`_select_ant_dropdown()` never falls back to the first option.** It returns a verified bool and leaves the field empty when the searched record is not in the list — picking whatever is alphabetically first would put a street the violation did not happen on into an official police report. `_fill_location_step()` uses that bool to retry the street against the next `mahalle_adaylari` entry.
- **Never press ESC to close an Ant Design dropdown popup** — it deselects the option you just picked. Use `_close_open_dropdowns()`, which dispatches a `mousedown` on `document.body` instead.
- Address suffix abbreviations returned by the site are unpredictable (`CADDESİ` might come back as `CD.` or `CAD.`). `split_address_suffix()` strips the suffix before searching so only the base name is typed, then `_select_ant_dropdown()` matches the returned options by suffix *family* (MAH/SK/CD/BLV) rather than exact string.
- Location dropdowns (city → district → neighborhood → street) are cascading and disabled until their parent's API call resolves — `_wait_for_enabled()` polls the `disabled` attribute with a short timeout per level rather than blocking indefinitely. The ids survived the redesign (`cityDropdown`, `districtDropdown`, `neighboorhoodDropdown`, `streetDropdown`), as did `description`, `name`, `surname`, `identityNumber`, `phoneNumber`, `email`, `address`.
- **The safety-unit radios are no longer `ant-radio-wrapper` labels.** Each option is a `<label>` card wrapping a fully transparent (`opacity-0`) `input[type=radio]`; the only identifier is `value` — Emniyet=1, Jandarma=4, Sahil Güvenlik=7 (usually `disabled`). `_select_guvenlik_birimi()` JS-clicks by value, falling back to the wrapping label.
- **KVKK consent is three hidden checkboxes** (`kvkk1`, `kvkk2`, `kvkk3`), replacing the old `checkAccessPersonelData`/`expliciptConsent` pair. They are `hidden`, so `_check_hidden_checkbox()` JS-clicks the input and falls back to the sibling `span` inside `label[for=...]` — never the `<button>` in that label, which opens the KVKK modal.
- **hCaptcha** (`id="h-captcha"`, sitekey `e4eefc1a-…`) sits on step 3 and is always solved by the user. Pressing that page's `Devam Et` is what triggers the SMS.
- **The SMS code is an Ant `Input.OTP`** — one `input` per digit under `.ant-otp`, not a single field with a guessable id. `_fill_otp()` types one character per box and deliberately does **not** press the confirm button.

## Other notes

- `arsiv/` holds old exploratory Selenium test scripts (from working out the quirks above) plus `form_filler_eski_site.py.bak`, the pre-redesign single-page filler kept for reference; the whole folder is gitignored and not part of the active pipeline.
- `gorseller/` (gitignored) holds frames extracted from videos; `ocr_helper.extract_frame_from_video()` is reused for this, so frame extraction has exactly one implementation.
- Turkish uppercasing must go through `turkish_upper()` in `form_filler.py`, not Python's built-in `.upper()` — Python's default mapping gets `i`→`I` and `ı`→`I` wrong for Turkish (should be `İ`/`I` respectively).
